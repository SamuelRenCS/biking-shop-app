  2. Hard parts and approach

  Problem: Tilted / slanted cards (hero, product cards, nav bar, active tab)
  Why it's hard in RN: A skewY transform would also skew the bike image and
  text.
  borderRadius only works on rectangles
  Approach: Draw the shape as a path with rounded corners in
  @shopify/react-native-skia (or react-native-svg), sized from onLayout, and
  render normal children on top. The slant is a fixed pt value, not an angle,
  so the cards look the same on both phones. The active nav tile is a plain
  rectangle with rotate: '-8deg', which is fine as a transform
  ────────────────────────────────────────
  Problem: Shadows on non-rectangular shapes
  Why it's hard in RN: iOS shadow* and the new boxShadow follow the view's
  rectangle and radius, not a custom path
  Approach: Draw the shadow inside the same Skia canvas (a Shadow image filter
  on
  the path). The canvas needs padding so the blur isn't clipped
  ────────────────────────────────────────
  Problem: Neumorphic raised/pressed surfaces
  Why it's hard in RN: Need inner shadows plus paired light and dark shadows
  Approach: Expo SDK 52+ runs RN 0.76+ with the New Architecture, which supports

  CSS-style boxShadow, including inset and multiple layers. That covers every
  rectangular neumorphic element without Skia. Check performance on long lists
  ────────────────────────────────────────
  Problem: Gradients (buttons, diagonal backgrounds, card fills, gradient border

  strokes)
  Why it's hard in RN: NativeWind's bg-gradient-* doesn't work on native
  Approach: expo-linear-gradient for rectangular gradient fills (buttons). Skia
  LinearGradient shaders for anything on a custom path: the diagonal
  background, card fills and the light border stroke
  ────────────────────────────────────────
  Problem: Diagonal background shape
  Why it's hard in RN: A shape that isn't a rectangle and sits behind scrolling
  content
  Approach: One absolutely positioned Skia path behind the ScrollView. On
  Discover it should probably scroll with the content (to be confirmed, see §5)
  ────────────────────────────────────────
  Problem: Staggered layouts
  Why it's hard in RN: Category chips and the offset product grid
  Approach: Chips: a fixed translateY per index, computed from the slant so they

  line up with the diagonal. Grid: two columns, with the right column given a
  negative top offset. Not a real masonry library
  ────────────────────────────────────────
  Problem: Cards scrolling under a slanted nav bar
  Why it's hard in RN: The nav top is diagonal, not flat
  Approach: Custom tabBar for expo-router Tabs, absolutely positioned. Add
  bottom
  padding to the ScrollView equal to the bar height plus the safe-area inset
  ────────────────────────────────────────
  Problem: Pixel-perfect type
  Why it's hard in RN: The font is Poppins (all weights are visible)
  Approach: @expo-google-fonts/poppins, mapped in Tailwind as
  font-poppins-semibold and so on. RN applies lineHeight differently from
  Figma, so set explicit line heights
  ────────────────────────────────────────
  Problem: Swipe-to-checkout and other motion
  Why it's hard in RN: Gesture plus animation
  Approach: Reanimated 3 with react-native-gesture-handler (both required by the

  brief)

  Skia works in Expo Go, so there's no dev-build cost. I'd use it only for the
  custom-path shapes and keep everything else in plain Views with NativeWind.

  4. Handling the two screen sizes

  - Layout widths use flex and percentages. Don't hardcode 390-based widths. The
    grid columns use (width − gutters − gap) / 2.
  - One useLayoutScale() hook: s = clamp(width / 390, 0.95, 1.1). Use it only
    for sizes tied to artwork: hero height, card heights, image boxes, slant
    amounts and chip offsets. Leave font sizes and padding unscaled (or scale
    them very lightly), because iOS users expect the same text size across
    phones and the Pro Max should show more content rather than bigger content.
  - Height:
    - Discover scrolls, so height doesn't matter.
    - On Detail, the carousel area flexes (flex-1, min/max height) and the sheet
      plus purchase bar keep their natural height. The description text scrolls
      inside the sheet if it overflows on the mini.
    - The Cart is a ScrollView with the Checkout button pinned. On the mini (812
      vs 844 pt) the summary will be ~30 pt tight, so the list scrolls.
  - Safe areas via react-native-safe-area-context: the mini has a notch and the
    17 Pro Max has the Dynamic Island, and their home-indicator insets differ.
    The bottom bar height is design height plus insets.bottom.
  - Check on both simulators from the first component onward, not at the end.
    I'd also add a dev-only overlay that shows the design PNG at 50% opacity,
    for pixel comparison on a 390-wide simulator (iPhone 16e/13).

  SVG or Skia

  I used Skia for the slanted shapes and plain Views everywhere else. The
  gradient and shadow alone would have worked in SVG, but this design needs
  three things SVG can't do well:
  - Figma's drop shadows: two shadows each, kept out from under the shape.
  - Glass cards: a blurred backdrop clipped to the slanted shape.
  - Overlay blend: the active tab tile's thin highlight edge.

  The SVG files themselves aren't loaded. They embed a 2.8 MB base64 image, so I
  copied their exact path geometry into code instead. Rectangles (buttons,
  chips) are plain Views, because RN 0.88 now supports CSS gradients and
  multi-layer boxShadow and the Figma values carry straight over.

  Theme

  tokens.ts (src/theme/tokens.ts) holds every color, gradient, shadow, radius
  and type size from the CSS, named by role. Tailwind, RN styles and Skia all
  read from it.

  What doesn't translate to RN:
  1. Slants: Figma's CSS export drops them entirely (the cards come out as plain
     rectangles). I rebuilt them from the shape SVGs' path data.
  2. backdrop-filter: blur: this has no RN equivalent. Because what sits behind
     the glass is our own drawing, Skia redraws it blurred inside the shape,
     which gives an exact result. I skipped the blur on the chips (it's
     invisible over a smooth gradient) and on the tab bar (its fill is opaque).
  3. filter: blur() (the soft shadows under the bikes): iOS only supports
     brightness and opacity, so these are drawn in Skia.
  4. mix-blend-mode: overlay: done in Skia.
  5. Gradient text (the active tab label on Detail): RN Text can't take a
     gradient, so it will need a mask in the Detail step.
  6. Inner hairline strokes (Figma's stroke-masked-by-shape): done with a Skia
     clip.
  7. Gradient stops outside 0–100%: RN handles them as-is; for Skia I fold them
     into the gradient's start and end points.
